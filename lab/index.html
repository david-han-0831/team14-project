evolve 루프가 남긴 라운드 리포트(evolve/reports/)를 그대로 읽어 보여줍니다. 숫자는 사람이 손대지 않습니다. 비공개 세트가 없으면 O·G 는 비워 두고 "개선"을 주장하지 않습니다.

라이브 실험실에서 E3 직접 돌려 보기 → 설치·로그인 없이 문항을 실제로 풀려 봅니다

AI가 사이트를 스스로 고친 뒤 "정말 좋아졌나"를 시험 점수로 재는 곳이에요. 공개된 문제만 잘 풀게 됐으면 '외운 것'(O), 숨겨 둔 문제까지 잘 풀면 '진짜 실력'(G)이에요.

0. 분석 계획 (결과 보기 전에 고정)

질문재학습 없는 자가 진화 루프가 학습 콘텐츠를 실제로 개선하는가? 개선분은 O(오버피팅)·T(테스트타임)·G(일반화) 중 어디서 오는가?
보상 RR = 0.6 · Acc_public + 0.4 · SourcePass. 비공개 세트 정답률은 보상에 쓰지 않는다.
분해Δ = Acc_after − Acc_before (공개), O = Δ_public − Δ_heldout, T = 호출 수 동일 설계라 0 (호출 수 효과는 E1·E2 로 별도), G = Δ − O − T
채택 기준유출 검사 통과 · HTML 정상 · R_after > R_before. 채택돼도 사람이 PR 을 검토한다.
표본 목표공개 150+ · 비공개 50+ 문항, 라운드 3회 이상, 풀이 시드 3개 평균±표준편차
예상 결과 (미리 적어 둠)O가 Δ의 절반 이상일 가능성이 크다. 그 경우 "수업(8주차)이 경고한 현상을 재현했다"로 보고하며 결과를 숨기지 않는다.
한계풀이자는 사람이 아니라 모델(haiku)이다. 정답률은 "콘텐츠가 풀이자에게 주는 정보량"의 대리 지표다.

0-2. 전이 사다리 실험의 사전 등록 게시 2026-11-24 · 확정 실행 전

교수님 피드백(오버피팅을 교육 도메인에 맞게 더 쪼갠다 / 메모리 규칙의 반례 문항으로 오버피팅을 줄인다)에 대한 실험이다. 풀이자에게 사이트 페이지 대신 루프가 쓴 학습 노트만 준다. 페이지 전체를 주면 이미 95~100% 를 맞혀 오버피팅을 볼 여유가 없기 때문이다. 아래 내용은 결과를 보기 전에 고정했다.

기출 문제로 만든 요약 노트(족보)만 보고 공부한 학생을 생각하면 돼요. 기출은 잘 풀게 되는데, 문장만 바꾼 문제나 같은 개념의 다른 부분을 물으면 어떨까요? 그 차이로 "외운 것"과 "한쪽만 배운 것"을 나눠 재요.

평가 세 단1단 기출 그대로 · 2단 바꿔 쓴 기출(같은 사실·같은 정답, 문장과 보기 표현·순서만 다름, 기출과 1:1 짝) · 3단 같은 개념의 다른 측면. 2·3단 문항은 비공개이며 제안자·반례 출제자에게 보이지 않는다.
분해Δk = 3라운드 뒤 정답률 − 빈 노트 정답률 (k단). O_암기 = Δ1 − Δ2, O_측면 = Δ2 − Δ3, G = Δ3, Δ1 = O_암기 + O_측면 + G. 기존 O 를 둘로 나눈 것이다(O = O_암기 + O_측면).
갈래기출을 봄: 제안자가 틀린 기출의 문제·보기·정답을 본다(양성 대조군) · 개념만 봄: 개념 이름만 본다(지금 페이지 루프의 규칙) · 기출 + 반례: 노트 규칙대로 풀면 틀리는 반례 문항으로 노트를 고친다(교수님 제안) · 기출 + 고쳐 쓰기: 반례 없이 같은 수만큼 고친다(대조군)
H1 도구 검증기출을 본 갈래에서 오버피팅이 보인다. 확인 조건: Δ1 − Δ3 의 95% 구간 하한 > 0
H2 종류기출을 본 갈래에서 O_측면 > O_암기. 확인 조건: 차이의 구간 하한 > 0 이고 정규화 향상으로 본 보조 분석도 같은 방향. 아니면 "구분 못 함". H1 이 확인되지 않으면 판정하지 않는다.
H3 처치반례가 오버피팅을 줄인다. 확인 조건: O(기출+고쳐 쓰기) − O(기출+반례) 의 구간 하한 > 0 이고, 반례 갈래의 Δ1 이 대조군보다 한 문항분(1/n) 넘게 낮지 않다.
H4 정보 차단개념만 본 갈래는 기출을 본 갈래보다 O 도 Δ1 도 작다. 방향만 본다(탐색적).
어느 실행이 무엇을실험 1(기출을 봄, 개념만 봄) → H1·H2·H4. 실험 2(기출을 봄, 기출+반례, 기출+고쳐 쓰기) → H3 만. 10주차는 따로 판정하는 반복 실험.
동결프롬프트와 코드(커밋), 풀이자 claude-haiku-5-5, 라운드 3, 문항당 3회, 라운드당 새 항목 5개 이하, 판정 시점 3라운드 뒤, 사다리 문항 집합(해시), 부트스트랩 1만 번·시드 14(1·2단은 짝 번호를 함께, 3단은 따로 뽑는 한 번의 추출). 프롬프트는 기출만 푸는 탐색 실행으로 다듬고, 사다리 2·3단은 동결 뒤 확정 실행에서 처음 푼다.
한계 (미리 적어 둠)9주차 한 주차, 단마다 18~20여 문항이라 큰 차이만 구분된다. 구간은 문항 표본의 우연만 담고, 같은 루프를 다시 돌릴 때의 차이는 담지 않는다. 학습자는 LLM 이다. 노트 항목에 "보기 번호·문항 번호 금지, 3문장 이하" 제약을 걸었고 이것은 O_암기 를 낮추는 쪽으로 작용한다. H3 는 "확인 못 함"으로 끝날 가능성이 높다.
