# 라이브 실험실 (Live Lab) 설계

작성 2026-11-21 · 담당 한동윤 · 상태: 검토 대기

## 1. 왜 만드는가

채점자가 저장소를 받아 `evolve/` 스크립트를 돌리면 Claude 구독이나 API 키가 없어 첫 호출에서 에러가 난다(11/15 예약 실행 실패와 같은 원인). 그래서 **배포된 URL에서 버튼 하나로 실험이 실제로 도는 페이지**를 만들고 README에 링크한다. 호출 비용은 한동윤의 Claude API 크레딧으로 내고, 수업이 끝나면 연결을 끊는다.

성공 기준:

- 링크를 연 사람이 설치·로그인 없이 E3(하네스 효과) 실험을 실행하고 결과를 본다.
- 실행에 쓰는 프롬프트·채점·자료 조건이 `evolve/` 연구 코드와 같다.
- API 키가 브라우저로 나가지 않는다.
- 키를 지운 뒤에도 페이지가 깨지지 않고 저장된 결과를 보여 준다.

## 2. 범위

포함: E3 실험의 라이브 실행(자료 없음 / 브리프 / 사이트 페이지), 실시간 진행 표시, 조건별 정답률과 신뢰구간, 기록된 결과와의 비교, 토큰·추정 비용 표시.

제외: 진화 루프 라운드(진단 → 패치 → 검증), E1·E2 실험, 로그인·접속 코드, 기존 사이트의 React 이전, 결과의 서버 저장.

## 4. 구조

```
live/                 React + Vite + TypeScript 화면 (빌드 결과 live/dist)
api/                  Vercel 파이썬 서버 함수
  _core.py            순수 로직 (문항 목록 · 풀이 · 리포트). 테스트 대상
  health.py           GET  /api/health
  bank.py             GET  /api/bank?set=week09
  solve.py            POST /api/solve
  reports.py          GET  /api/reports
tests/live/           _core.py 단위 테스트 (pytest, 가짜 풀이자)
vercel.json           빌드 명령 · 출력 폴더 · 함수에 포함할 파일
requirements.txt      anthropic
```

서버 함수는 `evolve/common.py` 와 `evolve/solve.py` 를 그대로 불러 쓴다: `load_bank`, `context_for`, `fmt_question`, `SYSTEM`, `parse_answer`, `is_correct`, `LLM`(api 백엔드). 연구 코드와 라이브 실행의 프롬프트가 갈라지지 않게 하기 위함이다. 함수 번들에는 `evolve/`, `assets/data/quiz/`, `content/briefs/`, `weeks/` 를 포함한다.

## 5. 실행 방식

브라우저가 문항 × 조건마다 `/api/solve` 를 한 번씩 부른다. 호출 하나가 몇 초라 서버 함수 시간 제한에 걸리지 않고, 결과가 한 칸씩 채워진다.

- 동시 요청 3개. "멈춤" 버튼으로 남은 요청을 취소한다.
- 실패한 칸은 한 번 재시도하고, 그래도 실패하면 "실패"로 표시한 채 계속한다. 실패 칸은 정답률 분모에서 빼고 개수를 따로 적는다.

## 6. 서버 함수

| 경로 | 입력 | 출력 |
|---|---|---|
| `GET /api/health` | — | `{live: bool, model, sets: [...]}`. `live` 는 API 키가 설정돼 있고 `LIVE_DISABLED` 가 아닐 때만 참 |
| `GET /api/bank?set=` | 세트 이름 | `{set, weeks, questions: [{id, week, type, q, options, concept}]}`. **정답·해설은 내려주지 않는다** |
| `POST /api/solve` | `{qid, condition}` | `{qid, condition, pred, correct, input_tokens, output_tokens, ms}` |
| `GET /api/reports` | — | `evolve/reports/exp-e3-*.json` 의 요약(조건별 정답률·CI·n·날짜) |

허용 값은 서버가 고정한다.

- 세트: `week09`(18문항, 기본), `seed`(2·4·8주차 39문항). 그 밖의 값은 400.
- 조건: `none`, `brief`, `page`. 그 밖의 값은 400.
- 모델 `claude-haiku-5-5`, effort `low`, 문항당 1회. 클라이언트가 바꿀 수 없다.

## 7. 비용 보호

1. **전용 API 키의 지출 한도**가 실제 상한이다. 한동윤이 Anthropic Console 에서 이 용도 전용 키를 만들고 한도를 건다.
2. 서버가 모델·문항·조건을 고정하므로 호출 하나의 크기가 정해져 있다. 9주차 1회 = 54회 호출, 연구 코드의 추정 단가로 약 0.06달러.
3. 접속은 링크를 아는 사람 누구나. 접속 코드는 두지 않는다.
4. `LIVE_DISABLED=1` 환경 변수로 키를 지우지 않고도 실행을 끌 수 있다.

## 8. 화면 (한 페이지)

1. 머리말: 무엇을 재는 실험인지 두 문장, 팀 사이트로 돌아가는 링크.
2. 세 조건 설명 카드와 세트 선택(9주차 / 시드), "실험 실행" · "멈춤" 버튼.
3. 진행 표: 행 = 문항, 열 = 세 조건. 칸은 대기 / 진행 중 / 정답 / 오답 / 실패.
4. 결과: 조건별 정답률 막대와 95% 신뢰구간(문항 단위 부트스트랩, `evolve/solve.py` 와 같은 방식), 자료 없음에서 틀리고 자료가 있을 때 맞힌 문항 목록.
5. 기록된 결과와 비교: 같은 세트의 저장된 리포트 값을 나란히 표시.
6. 사용량: 호출 수, 토큰, 추정 비용.

키가 없거나 꺼져 있으면 2~3번 대신 "라이브 실행은 종료됐습니다" 안내를 띄우고 5번(기록된 결과)만 보여 준다.

스타일은 기존 `assets/css/site.css` 의 색·글꼴 변수를 따른다. 선택·강조 표시에 왼쪽 세로줄을 쓰지 않는다. 라이트·다크, 모바일 폭(375px)에서 가로 넘침이 없어야 한다.

## 9. 오류 처리

| 상황 | 서버 | 화면 |
|---|---|---|
| 키 없음 · 실행 꺼짐 | `/api/solve` 503 | 종료 안내 + 기록된 결과 |
| 잘못된 세트·조건·문항 | 400 | 발생하지 않아야 함(화면이 허용 값만 보냄). 발생 시 오류 문구 |
| Claude 호출 실패·한도 초과 | 502 / 429 | 해당 칸 "실패", 연속 실패가 이어지면 실행을 멈추고 안내 |
| 답 형식을 못 읽음 | 200, `pred: null`, `correct: false` | 오답으로 집계(연구 코드와 같은 규칙) |

## 10. 검증

- `tests/live/`: 세트·조건 검증, 정답이 응답에 섞이지 않는지, 가짜 풀이자로 채점 결과가 맞는지.
- 화면 통계 함수(정답률·부트스트랩) 단위 테스트.
- 로컬에서 가짜 풀이자 모드(`LIVE_MOCK=1`)로 실행 → 멈춤 → 재실행까지 브라우저로 확인.
- 실제 키로 도는지는 한동윤이 Vercel 에 키를 넣은 뒤 배포본에서 9주차 1회를 돌려 확인한다. 기록된 결과(자료 없음 66.7% · 브리프 100% · 페이지 94.4%)와 크게 어긋나지 않는지 본다.

## 11. 사람이 직접 해야 하는 일

- Anthropic Console 에서 전용 API 키 발급과 지출 한도 설정 (한동윤).
- Vercel 프로젝트 환경 변수 `ANTHROPIC_API_KEY` 입력 (한동윤). 키 값은 저장소·문서·대화에 남기지 않는다.
- 수업이 끝나면 그 환경 변수를 지우거나 `LIVE_DISABLED=1` 을 넣는다.
- 팀 저장소 main 반영 (통합 담당).
