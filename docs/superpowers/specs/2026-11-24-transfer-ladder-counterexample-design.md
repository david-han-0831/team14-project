# 전이 사다리와 반례 처치 설계

작성 2026-11-24 · 담당 손재완(통합) · 상태: 검토 대기

교수님 중간발표 피드백에 대한 대응 설계다. 한 문장으로: **자가 진화가 만든 오버피팅을 교육의 "전이" 관점으로 두 종류로 쪼개고, 교수님이 제안한 "메모리 규칙의 반례 문항"이 그중 무엇을 줄이는지 잰다.**

## 1. 왜 만드는가

### 1.1 받은 피드백 (2026-11-23 중간발표)

- 지금 주제(개선분이 어디서 오는지 분해, 교육 콘텐츠에 적용)는 괜찮다.
- 시간이 되면 한 걸음 더. 두 방향을 예로 드셨다.
  - **교육 쪽**: O + T + G 를 그대로 가져오지 말고 교육 도메인에 맞게 더 쪼갠다. 예: 오버피팅의 종류를 나눈다.
  - **ML 쪽**: 자가 진화는 메모리에 적힌 규칙대로 결정해서 오버피팅이 난다. 그 규칙대로 풀면 틀릴 문제를 만들어 학습시키면 규칙이 완화되지 않을까.

### 1.2 지금 상태로는 둘 다 할 수 없는 이유

11/24 실측(9주차, `evolve/reports/`)에서 O 는 +0.02 로 잡음 수준이었다. 오버피팅이 없어서가 아니라 **볼 수 없는 설정**이기 때문이다. 풀이자가 사이트 페이지 전체를 받으면 이미 거의 다 맞힌다.

| 풀이자 | 세트 | 자료 없음 | 페이지 제공 |
|---|---|---|---|
| Haiku 5.5 (현재 풀이자) | 공개 9주차 18문항 | 67~74% | 98~100% |
| Haiku 5.5 | 비공개 9주차 20문항 | 65% | 95% |
| Haiku 4.5 (이전 세대) | 공개 9주차 18문항 | 61% | 83% |

(마지막 두 줄과 첫 줄 일부는 11/24 탐색 실행, k=1. 리포트 파일로는 남기지 않았다.)

O 가 0.02 인 곳에서는 O 를 쪼개도, 줄이는 기법을 붙여도 보여 줄 차이가 없다. 그래서 첫 과제는 **오버피팅이 실제로 크게 나타나는 설정**을 만드는 것이다.

## 2. 무엇을 보이려는가

### 2.1 질문

1. (도구) 우리 측정이 오버피팅을 잡아내는가. 일부러 오버피팅하게 만든 루프에서 O 가 뚜렷이 나오는가.
2. (교육 쪽) 그 오버피팅은 "문항을 외운 것"인가, "개념의 한 측면만 배운 것"인가.
3. (ML 쪽) 메모리 규칙의 반례 문항으로 노트를 고치면 어느 쪽 오버피팅이 줄어드는가. 공개 점수는 얼마나 잃는가.

### 2.2 목표

- 오버피팅이 관찰되는 실험 설정(노트 루프)을 만든다.
- O 를 `O_암기 + O_측면` 으로 나누는 측정 도구(전이 사다리)를 만든다.
- 반례 처치를 구현하고, 처치 유무를 같은 문항으로 비교한다.
- 결과를 실험실 페이지에 그림 하나로 보여 준다.

### 2.3 하지 않는 것

- 사이트 주차 페이지를 이 실험으로 고치지 않는다. 기존 페이지 패치 루프(`evolve/round.py`)는 그대로 둔다.
- 모델 재학습·파인튜닝은 없다. "학습시킨다"는 노트를 고쳐 쓴다는 뜻이다.
- 사람 학습자 실험은 없다. 모든 "학습 효과"는 LLM 풀이자를 학습자 대리로 쓴 결과다.
- 2·4·8주차 공개 시드를 어렵게 고치는 일은 이 설계 범위 밖이다(이슈 #15).

### 2.4 이렇게 되면 실패다

- 평가용 문항(전이 사다리, 비공개 세트)이 제안자·반례 출제자에게 보이거나 공개 저장소에 들어간다.
- 신뢰구간이 겹치는 차이를 "줄였다"고 발표한다.
- 가짜 풀이자(mock) 수치나 탐색 실행 수치가 실측 결과처럼 그림에 들어간다.
- 반례 처치가 효과 없다는 결과가 나왔을 때 조건을 바꿔 가며 효과가 나올 때까지 다시 돌린다(3.6 의 사전 등록으로 막는다).

## 3. 설계

### 3.1 접근 방식 비교

| 안 | 내용 | 얻는 것 | 문제 |
|---|---|---|---|
| 1안 교육 | O 를 전이 거리로 쪼갠다 | 교육 도메인에 맞춘 새 분해 | 측정뿐이고 고치는 방법이 없다 |
| 2안 ML | 반례 문항으로 오버피팅을 줄인다 | 교수님 아이디어의 구현과 검증 | O 를 재는 도구가 약하면 효과를 못 보인다 |
| **3안 (선택)** | 1안을 측정 도구로, 2안을 처치로 | "반례가 어떤 종류의 오버피팅을 줄이는가" | 일이 가장 많다. 단계별로 끊어서 해결(4절) |

사용자가 3안을 골랐다(2026-11-24).

실험 무대도 세 가지를 비교했다.

| 무대 | 풀이자가 보는 것 | 출발 정답률 | 판단 |
|---|---|---|---|
| 페이지 전체 (지금) | 주차 페이지 본문 | 98~100% | 천장. 탈락 |
| 페이지 전체 + 약한 풀이자 | 주차 페이지 본문, Haiku 4.5 | 83% | 여유 17%p. 지금까지의 모든 기록과 풀이자가 달라진다 |
| **노트만 (선택, 내 판단)** | 루프가 쓴 학습 노트만 | 65~74% | 여유 30%p 안팎. 교수님이 말한 "메모리의 규칙" 구도와 같다 |

노트만 주는 무대를 고른 이유: (1) 여유 공간이 가장 크다. (2) 풀이자가 답할 때 쓰는 지식이 전부 루프가 쓴 노트에서 오므로 "규칙 때문에 생긴 오버피팅"을 직접 본다. (3) 교육 비유가 분명하다: 기출 문제로 만든 요약 노트(족보)만 보고 공부한 학생.

### 3.2 용어

| 말 | 뜻 |
|---|---|
| 학습 노트 | 루프가 라운드마다 고쳐 쓰는 규칙 목록. 교수님이 말한 "메모리". 주차·갈래별로 하나 |
| 노트 항목 | 노트의 한 줄. 개념 이름, 규칙 문장(2문장 이하), 출처 |
| 갈래 | 제안자·처치 조합. 3.4 의 세 가지 |
| 기출 | 공개 세트 문항(`assets/data/quiz/`). 루프가 점수를 올리려는 대상 |
| 전이 사다리 | 기출에서 멀어지는 정도에 따라 나눈 평가 문항 세 단 |
| 반례 문항 | 노트 규칙을 글자 그대로 따르면 틀리도록 만든 문항. 노트를 고치는 데만 쓴다 |

### 3.3 노트 루프

기존 페이지 루프와 나란히 두는 새 루프다. 한 라운드:

```
① 풀이   풀이자가 [노트만] 보고 기출을 푼다 (문항당 3회)
② 진단   한 번이라도 틀린 문항과 그 개념을 뽑는다 (기존 diagnose 재사용)
③ 제안   제안자가 노트 항목을 쓴다 (갈래마다 보는 것이 다름, 3.4)
④ 처치   (반례 갈래만) 반례 문항으로 노트를 고친다 (3.5)
⑤ 평가   새 노트로 전이 사다리 세 단을 모두 푼다 (문항당 3회)
```

- 0라운드 노트는 비어 있다. 이때의 평가가 기준선이며 "자료 없음" 조건과 같다. 세 갈래가 기준선을 공유한다.
- 라운드 수 3. 라운드당 새 항목은 최대 5개. 노트는 누적된다.
- 풀이자는 `claude-haiku-5-5` (지금까지의 기록과 같은 모델). 제안자·반례 출제자는 `claude-opus-5-5`.
- 풀이자 호출 수는 모든 갈래·라운드에서 같다. 따라서 T = 0 (기존 분해와 같은 처리).
- 대상 주차: 9주차부터. 8주차 공개 시드는 자료 없이 100% 라 여유가 없어 제외. 10주차는 공개 문제 은행을 만든 뒤 추가(4절 2단계).

### 3.4 세 갈래

| 갈래 | 제안자가 보는 것 | 역할 |
|---|---|---|
| `seen` 기출을 보는 제안자 | 틀린 기출의 문제·보기·정답, 브리프 | 양성 대조군. 실제 자가 진화 에이전트(틀린 궤적을 보고 반성)와 같은 조건. 오버피팅이 가장 크게 나와야 한다 |
| `concept` 개념만 보는 제안자 | 틀린 기출의 개념 이름, 브리프 | 지금 페이지 루프의 규칙. 정보를 막아서 오버피팅을 줄이는 기준 방법 |
| `seen+ce` 기출을 보는 제안자 + 반례 처치 | `seen` 과 같음 + 반례 문항 결과 | 교수님 제안. `seen` 과 비교한다 |

누가 무엇을 보는가 (이 표가 유출 방지 규칙이다):

| | 기출 | 브리프 | 노트 | 반례 문항 | 사다리 2·3단 |
|---|---|---|---|---|---|
| 풀이자 | 문제만 | × | ○ | 문제만 | 문제만 |
| 제안자 `seen` | 문제·정답 | ○ | ○ | (ce 갈래) 문제·정답 | **×** |
| 제안자 `concept` | 개념 이름만 | ○ | ○ | × | **×** |
| 반례 출제자 | **×** | ○ | ○ | 자기가 쓴 것 | **×** |

### 3.5 반례 처치

교수님 말씀("메모리 규칙대로 풀면 틀릴 문제를 만들어 학습시킨다")을 그대로 옮긴 것이다.

1. **출제**: 반례 출제자가 노트 항목마다 객관식 1~2문항을 쓴다. 조건: 항목의 규칙을 글자 그대로 또는 넓혀서 적용하면 고르게 되는 **함정 보기**가 하나 있고, 브리프 원문으로는 다른 보기가 정답이다. 문항마다 정답 근거 문장(브리프 인용)과 함정 보기 번호를 함께 낸다.
2. **거르기**: (a) 기계 검사: 형식, 보기 4개, 정답·함정이 서로 다름, 기출과 문장 중복 아님. (b) 브리프를 본 강한 풀이자(`claude-sonnet-5-5`)가 2회 모두 맞혀야 한다. 못 맞히면 문항 결함으로 보고 버린다.
3. **풀기**: 풀이자가 현재 노트만 보고 반례 문항을 푼다(3회).
4. **고치기**: 한 번이라도 틀린 반례가 있으면 제안자에게 [해당 노트 항목, 그 반례 문항과 정답, 브리프]를 주고 항목을 고쳐 쓰게 한다. 허용되는 수정: 조건·예외·적용 범위 추가, 규칙 일반화, 항목 삭제.
5. 1~4 를 라운드당 최대 2번 되풀이한다.

기록하는 지표:

- **함정 선택률**: 풀이자가 함정 보기를 고른 비율. 노트가 얼마나 좁은 규칙인지의 직접 지표.
- 반례 통과율(거르기 통과 수 / 출제 수), 수정된 항목 수, 삭제된 항목 수.

반례 문항은 학습용이다. 평가에는 쓰지 않는다.

### 3.6 전이 사다리와 분해

기출에서 멀어지는 세 단으로 평가한다.

| 단 | 문항 | 떨어지면 뜻하는 것 | 만드는 법 |
|---|---|---|---|
| 1단 기출 | 공개 세트 그대로 | (기준) | 있음 (9주차 18문항) |
| 2단 바꿔 쓴 기출 | 기출과 같은 사실·같은 정답, 문장과 보기 표현·순서만 다름. 기출과 1:1 짝 | 문항을 외웠다 | 새로 출제 (기출당 1문항) |
| 3단 다른 측면 | 같은 개념, 다른 사실·사례 | 개념의 한 측면만 배웠다 | 기존 비공개 세트 중 근거가 그 주차 브리프에 있는 문항(9주차 15개) + 부족분 새로 출제 |

갈래별로 기준선(빈 노트) 대비 향상을 단마다 잰다: `Δ1`, `Δ2`, `Δ3`.

```
O_암기 = Δ1 − Δ2      문장이 바뀌면 사라지는 향상
O_측면 = Δ2 − Δ3      다른 측면을 물으면 사라지는 향상
G      = Δ3           다른 측면까지 살아남는 향상
Δ1     = O_암기 + O_측면 + G          (T = 0)
```

기존 분해 `Δ = O + T + G` 에서 `O = O_암기 + O_측면` 으로 한 번 더 나눈 것이다. 기존 식과 모순되지 않는다.

교육학과의 연결(발표 전에 원문을 확인하고, 확인 전까지는 "확인 필요"로 표기한다):

- 2단 → 3단은 근접 전이와 원거리 전이의 구분(Barnett & Ceci, 2002 의 전이 분류).
- `O_암기` 는 "시험에 맞춘 수업"으로 생기는 점수 부풀림(Koretz 의 score inflation 논의).
- 넷째 단(객관식을 숫자·서술형으로 바꿔 "시험 요령"을 재는 단)은 이번 범위에서 뺐다. 5절에 적는다.

통계:

- 문항별 향상 = (노트 있을 때 3회 평균) − (빈 노트 3회 평균).
- `O_암기` 는 1단·2단이 짝이므로 문항별 차이의 평균. 문항 단위 부트스트랩(1만 번, 시드 고정) 95% 구간.
- `O_측면`, `G` 는 문항 단위 부트스트랩(단마다 독립 추출).
- 갈래 간 비교(`seen` 대 `seen+ce`)는 같은 문항이므로 같은 추출 번호로 차이를 낸다.
- 구간이 0 을 포함하면 "차이를 확인하지 못했다"고 쓴다.

사전 등록(결과를 보기 전에 고정. `lab/index.html` 의 사전 등록 칸에 같은 내용을 올린다):

| | 예측 | 판정 |
|---|---|---|
| H1 도구 검증 | `seen` 갈래에서 `O_암기 + O_측면 > 0` | 95% 구간이 0 을 넘으면 확인 |
| H2 종류 | `O_측면 > O_암기` (노트는 문장보다 사실을 담으므로) | 차이의 구간이 0 을 넘으면 확인. 아니면 "구분 못 함" |
| H3 처치 | `seen+ce` 의 `O_암기 + O_측면` 이 `seen` 보다 작고, `Δ1` 손실은 5%p 이내 | 둘 다 만족해야 확인 |
| H4 정보 차단 | `concept` 은 `seen` 보다 O 도 작고 `Δ1` 도 작다 | 방향만 보고(탐색적) |

- 라운드 수(3), 문항당 풀이 횟수(3), 풀이자 모델, 갈래 정의는 첫 실측 실행 뒤에는 바꾸지 않는다. 바꾸면 새 실험으로 번호를 달리해 둘 다 남긴다.
- H1 이 확인되지 않으면 H2·H3 는 판정하지 않고 "도구가 오버피팅을 잡지 못했다"로 보고한다.

### 3.7 파일과 인터페이스

공개 저장소:

```
evolve/notes.py         노트 읽기·쓰기, 풀이자용 텍스트 만들기
evolve/note_round.py    노트 루프 실행 (갈래, 라운드 수)
evolve/counter.py       반례 출제 · 거르기 · 풀기 · 고치기
evolve/ladder.py        사다리 평가와 분해, 부트스트랩
evolve/notes/<갈래>/weekNN.json          라운드별 노트 (공개. 실험 산출물)
evolve/reports/ladder-weekNN.json        갈래 × 라운드 × 단의 정답률, 분해, 구간, 반례 지표
```

- `common.context_for(week, "notes", ...)`: 풀이 조건 `notes` 추가. `solve.py --condition notes --arm seen`.
- `common.load_bank("ladder", weeks)`: 사다리 2·3단을 비공개 위치에서 읽는다. 문항에 `rung`("T2"|"T3"), 2단 문항에는 `pair`(짝이 되는 기출 id).
- `common.PRICE` 에 `claude-haiku-4-5` 추가(지금은 표에 없어 추정 비용이 수십 배로 잡힌다).
- 노트 형식: `{"week", "arm", "round", "entries": [{"id", "concept", "rule", "sources", "origin": {"round", "from": "public-fail"|"counterexample"}, "history": [...]}]}`
- 가짜 풀이자(`--mock`)로 전 과정을 돌릴 수 있어야 한다. mock 리포트는 `mock: true` 로 표시되고 실험실 페이지에서 구분된다(기존 규칙).

비공개 위치(`team14-heldout`, 공개 저장소에 넣지 않는다):

```

work/ladder/week09/                        출제 · 검사 · 풀이 · 검증 기록
```

- 2단은 quiz-writer 로 출제하고, quiz-verifier 가 "기출과 사실·정답이 같은가, 표현이 실제로 다른가"를 기출과 나란히 놓고 확인한다. 강한 풀이자 2회 모두 정답이어야 한다.
- 3단 추가분은 11/24 비공개 세트와 같은 절차(수정 라운드 포함)로 만든다. 근거가 그 주차 브리프에 있는 문항만 넣는다.

### 3.8 비용과 시간

- 평가 한 번 = (18 + 18 + 15~18) × 3 ≈ 160 호출. 기준선 1번 + 세 갈래 × 3라운드 = 10번 ≈ 1,600 호출.
- 루프 안 풀이·반례 포함 9주차 한 번에 약 2,200 호출. 호출당 약 4초이므로 갈래를 따로 돌리면 1시간 안쪽.
- 구독 사용량으로 실행(`EVOLVE_CLI_ISOLATION=--safe-mode`). API 환산 추정 3~5달러.

## 4. 단계 (끊겨도 발표할 수 있는 순서)

최종발표가 11/30 인지 12/7 인지 미정이다. 11/30 을 기준으로 짜고 12/7 이면 3·4단계를 넓힌다.

|---|---|---|
| 1 | 노트 루프(`seen`, `concept`) + 9주차 2단 출제 + 사다리 평가 | H1: 도구가 오버피팅을 잡는가. H2: 어떤 종류인가 |
| 2 | 실험실 "전이 사다리" 칸, 사전 등록 게시, 10주차 공개 은행과 사다리 | 그림. 표본 두 배 |

## 5. 한계 (발표에도 그대로 쓴다)

- 표본이 작다. 9주차 한 주차는 단마다 15~18문항이다. 큰 차이만 구분된다.
- 학습자는 LLM 이다. 사람 학생의 전이와 같다고 주장하지 않는다.
- 사다리 2·3단 문항도 LLM 이 출제했다. 검증자와 강한 풀이자로 걸렀지만 사람 전문가 검토는 없다.
- "노트만" 무대는 사이트 페이지와 다르다. 사이트 페이지 루프의 결과(천장 때문에 판별 불가)는 따로 보고한다.
- 넷째 단(문제 형식 전이)과 여러 주차에 걸친 원거리 전이는 다루지 않았다.
