# 라이브 실험실 (Live Lab) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 배포된 URL에서 버튼 하나로 E3(하네스 효과) 실험이 서버 측 Claude API 키로 실제로 돌고, 결과가 실시간으로 보이는 페이지를 만든다.

**Architecture:** 브라우저(React)가 문항 × 조건마다 `/api/solve` 를 한 번씩 부르고, Vercel 파이썬 서버 함수가 기존 `evolve/` 코드로 프롬프트를 만들어 Claude 를 호출하고 채점한다. 서버 로직은 `livelab/` 패키지 한 곳에 두고 `api/*.py` 와 로컬 개발 서버가 같은 로직을 부른다.

**Tech Stack:** Python 3.12 · anthropic SDK(기존 `evolve/common.py` 의 `LLM` 재사용) · pytest · React 18 + Vite + TypeScript · vitest · Vercel(파이썬 함수 + 정적 빌드).

**Spec:** `docs/superpowers/specs/2026-11-21-live-lab-design.md`

## Global Constraints

- 모델 `claude-haiku-5-5`, effort `low`, 문항당 1회. 클라이언트가 바꿀 수 없다.
- 세트는 `week09`(18문항), `seed`(2·4·8주차 39문항) 둘뿐. 조건은 `none` · `brief` · `page` 셋뿐.
- `/api/bank` 응답에 정답(`answer`)·해설(`explain`)이 들어가면 안 된다.
- API 키 값은 저장소·문서·로그·대화에 남기지 않는다. 환경 변수 이름: `ANTHROPIC_API_KEY`, `LIVE_DISABLED`, `LIVE_MOCK`.
- `evolve/*.py` 는 수정하지 않는다(불러 쓰기만). 기존 정적 사이트는 `README.md` 와 `lab/index.html` 의 링크 추가 외에 건드리지 않는다.
- 화면 문구는 한국어. 선택·강조 표시에 왼쪽 세로줄(left border / inset shadow)을 쓰지 않는다.
- 색·글꼴은 `assets/css/site.css` 의 `:root` 변수 값과 다크 모드 값을 그대로 쓴다.
- 라이트·다크, 폭 375px 에서 가로 넘침 없음.
- 커밋 메시지 끝에 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **잘못된 요청 본문** (JSON 아님, 필드 누락, 문자열이 아닌 값) → 500 이 아니라 400 과 오류 문구. (Task 2 테스트)
2. **실행 중 Claude 한도 초과·과부하** → 해당 칸만 "실패", 실행은 계속. 연속 5칸 실패면 멈추고 안내. (Task 3 runner 테스트)
3. **실행 중 키가 꺼짐**(503) → 즉시 멈추고 종료 안내로 전환. (Task 3 runner 테스트)
4. **실행 버튼 연타, 멈춤 직후 재실행** → 요청이 중복되지 않고 이전 실행의 늦은 응답이 새 표에 섞이지 않는다. (Task 3 runner 테스트)
5. **한 조건의 칸이 전부 실패** → 정답률이 `NaN` 이나 0% 가 아니라 "—" 로 표시된다. (Task 3 stats 테스트)

### Task 3: 화면 로직 (통계 · API 클라이언트 · 실행기)

**Files:**
- Create: `live/package.json`, `live/vite.config.ts`, `live/tsconfig.json`, `live/index.html`, `live/src/lib/stats.ts`, `live/src/lib/api.ts`, `live/src/lib/runner.ts`

**Interfaces:**
- Vite 개발 서버는 `/api` 를 `http://127.0.0.1:8787` 로 프록시한다. `npm run test` = `vitest run`, `npm run build` = `tsc -b && vite build`.
- `api.ts`:
  - 타입 `Condition = "none" | "brief" | "page"`, `Question = {id, week, type: "mc" | "num", q, options: string[] | null, concept}`, `SolveResult = {qid, condition, pred, correct, input_tokens, output_tokens, ms}`, `Health`, `Report`.
  - `getHealth()`, `getBank(set)`, `getReports()`, `postSolve(qid, condition, signal)`.
  - `class ApiError extends Error { status: number }` — 2xx 가 아니면 던진다.
- `stats.ts`:
  - `accuracy(values: number[]): number | null` — 빈 배열이면 `null`.
  - `bootstrapCI(values: number[], nBoot = 2000, seed = 14): [number, number] | null` — 문항 단위 재표집 평균의 2.5·97.5 백분위. 난수는 시드 고정 mulberry32. 빈 배열이면 `null`. (파이썬 구현과 난수기가 달라 셋째 자리에서 다를 수 있다. 화면에 "브라우저에서 계산"이라고 적는다.)
  - `formatPct(v: number | null): string` — `null` → `"—"`, 그 외 소수 첫째 자리 `%`.
- `runner.ts`:
  - `type Cell = {status: "idle" | "running" | "ok" | "wrong" | "failed"; result?: SolveResult}`
  - `runExperiment(opts: {questions: Question[]; conditions: Condition[]; solve: (qid, cond, signal) => Promise<SolveResult>; signal: AbortSignal; onCell: (qid, cond, cell) => void; concurrency?: number}): Promise<{stopped: "done" | "aborted" | "disabled" | "too-many-failures"}>`
  - 규칙: 동시 3. 칸마다 실패 시 1회 재시도. `ApiError.status === 503` 이면 즉시 `"disabled"` 로 끝낸다. 재시도 후에도 실패한 칸이 **연속 5개**면 `"too-many-failures"`. `signal` 이 취소되면 새 요청을 시작하지 않고 `"aborted"`. 끝난 뒤(또는 취소 뒤) 도착한 응답으로 `onCell` 을 부르지 않는다.

- [ ] **Step 1: 실패하는 테스트 작성**

```ts
// stats.test.ts
test("accuracy of empty is null, not NaN", () => { expect(accuracy([])).toBeNull(); expect(formatPct(null)).toBe("—"); });
test("accuracy 12/18", () => expect(accuracy([...Array(12).fill(1), ...Array(6).fill(0)])).toBeCloseTo(0.6667, 4));
test("CI of all-correct is [1, 1]", () => expect(bootstrapCI(Array(18).fill(1))).toEqual([1, 1]));
test("CI brackets the mean and is deterministic", () => {
  const v = [...Array(12).fill(1), ...Array(6).fill(0)];
  const [lo, hi] = bootstrapCI(v)!; expect(lo).toBeLessThan(0.6667); expect(hi).toBeGreaterThan(0.6667);
  expect(bootstrapCI(v)).toEqual([lo, hi]);
});
test("formatPct", () => expect(formatPct(0.9444)).toBe("94.4%"));

// runner.test.ts  (가짜 solve 로 검증)
test("runs every question × condition once with at most 3 in flight");          // 호출 수 = 문항×조건, 동시 실행 최대값 ≤ 3
test("retries a failed cell once, then marks it failed and continues");         // 2회 호출 후 status "failed", 나머지 칸은 ok
test("stops with 'too-many-failures' after 5 consecutive failed cells");
test("stops with 'disabled' on a 503 and starts no further requests");
test("abort: no new requests start and late responses do not call onCell");
```
