# 최종 발표용 결과 요약 (2026-11-25 기준)

발표자료(11/29 제출, 12/7 발표)에 넣을 내용을 한곳에 모았다. 수치는 모두 `evolve/reports/` 의 리포트에서 그대로 옮긴 것이며, 실험실 페이지(https://wukong-daima.github.io/team14-project/lab/)에서 확인할 수 있다. 여기 없는 수치는 발표에 쓰지 않는다.

## 1. 한 문장

**자가 진화 루프는 공개 문제 점수를 크게 올렸지만(+30%p), 그 향상이 "외운 것"인지 "배운 것"인지는 이 표본으로 확정하지 못했다. 방향은 두 번 모두 "다른 측면으로는 덜 옮겨 간다"였다.**

## 2. 교수님 피드백과 우리가 한 일

| 피드백 | 한 일 |
|---|---|
| O + T + G 를 교육 도메인에 맞게 더 쪼갤 수 있지 않나 | 오버피팅을 교육의 "전이" 관점으로 둘로 나눴다: `O_암기`(문장이 바뀌면 사라지는 향상), `O_측면`(같은 개념의 다른 측면을 물으면 사라지는 향상) |
| 메모리 규칙대로 풀면 틀릴 문제를 만들어 학습시키면 오버피팅이 줄지 않을까 | 노트 규칙의 반례 문항을 만들어 노트를 고치는 처치를 구현하고, 반례 없이 같은 횟수만큼 고치기만 한 대조군과 비교했다 |

먼저 풀어야 했던 문제: 풀이자에게 사이트 페이지 전체를 주면 이미 95~100% 를 맞혀 오버피팅을 볼 여유가 없었다(11/24 라운드, O +0.02). 그래서 풀이자에게 **루프가 쓴 학습 노트만** 주는 설정을 만들었다(기출 문제로 만든 요약 노트만 보고 공부한 학생).

## 3. 측정 방법 (슬라이드 한 장)

```
평가 세 단                              분해
 1단 기출 그대로            ┐
 2단 바꿔 쓴 기출 (1:1 짝)  ├─ Δk = 3라운드 뒤 정답률 − 빈 노트 정답률
 3단 같은 개념의 다른 측면  ┘
                                        O_암기 = Δ1 − Δ2
                                        O_측면 = Δ2 − Δ3
                                        G      = Δ3          (Δ1 = O_암기 + O_측면 + G)
```

- 9주차, 문항 18 / 18 / 20, 풀이자 Claude Haiku 5.5, 문항당 3회, 3라운드.
- 2·3단 문항은 비공개. 제안자·반례 출제자에게 보이지 않는다.
- **결과를 보기 전에 가설·판정 기준·코드·문항 집합을 고정했다(사전 등록).** 실험실 페이지 0-2.

## 4. 결과

### 실험 1 — 오버피팅이 잡히는가 (확정 실행, 2026-11-24)

빈 노트 기준선: 1단 68.5% · 2단 74.1% · 3단 68.3%. 아래는 기준선 대비 향상(%p)과 95% 구간.

| 제안자가 보는 것 | 1단 기출 | 2단 바꿔 씀 | 3단 다른 측면 | O = 1단 − 3단 |
|---|---|---|---|---|
| 틀린 기출의 문제·정답 | +29.6 | +24.1 | +8.3 [0.0, +20.0] | **+21.3 [−2.2, +45.4]** |
| 개념 이름만 | +31.5 | +25.9 | +26.7 [+8.3, +48.3] | +4.8 [−24.1, +33.9] |

- **H1 (기출을 본 제안자에서 O > 0): 확인 못 함.** 구간 하한이 −2.2%p 로 0 을 넘지 못했다.
- H2 (어떤 종류의 오버피팅인가): 사전 등록대로 판정하지 않음. 점추정은 `O_암기` +5.6, `O_측면` +15.7.
- 그림: `submission/img/final_ladder_exp1.png`

### 실험 2 — 반례 처치 (탐색적, 2026-11-25)

실험 1 에서 H1 이 확인되지 않았으므로 **H3 는 판정하지 않는다.** 방향만 본다. 기준선: 70.4% · 81.5% · 65.0%.

| 갈래 | 1단 기출 | 3단 다른 측면 | O = 1단 − 3단 |
|---|---|---|---|
| 기출을 봄 (처치 없음) | +29.6 | +10.0 [−1.7, +23.3] | +19.6 [−3.7, +43.1] |
| 기출 + 반례 | +29.6 | +15.0 [+3.3, +28.3] | +14.6 [−8.2, +37.8] |
| 기출 + 고쳐 쓰기 (대조군) | +29.6 | +18.3 [+5.0, +33.3] | +11.3 [−12.8, +35.7] |

- O(고쳐 쓰기) − O(반례) = −3.3 [−11.7, +3.3]. **반례 처치와 단순 고쳐 쓰기를 구분하지 못했다.**
- 반례 10문항 출제, 10문항 모두 거르기 통과. 풀이자의 함정 선택률은 첫 회차 13~17%.
- 그림: `submission/img/final_ladder_exp2.png`

## 5. 말할 수 있는 것과 없는 것

| 말할 수 있다 | 말하면 안 된다 |
|---|---|
| 독립된 두 실행에서 같은 방향·비슷한 크기(O 약 +20%p)가 나왔다 | "오버피팅을 확인했다" |
| 사전 등록한 기준(구간 하한 > 0)에는 두 번 다 근소하게 못 미쳤다 | "오버피팅이 없었다" |
| 반례 처치는 단순 고쳐 쓰기와 구분되지 않았다 | "반례가 효과 있다" / "효과 없다" |
| 정규화해서 보면 1·2단은 올라갈 수 있는 만큼 다 올랐고 차이는 3단에서만 났다 | "암기형 오버피팅은 없다"(제약을 걸어 둔 조건에서의 관찰이다) |
| 개념 이름만 본 제안자의 노트가 다른 측면에서 더 높았다(95% 대 76.7%) | 이것을 확정된 결과처럼 말하기(구간이 0 에 닿는 탐색적 관찰) |

## 6. 관찰 (탐색적, 해석 주의)

1. **이 설정의 오버피팅은 "틀린 규칙의 과잉 적용"보다 "노트가 다른 측면을 덮지 못함"에 가깝다.** 풀이자가 반례의 함정 보기를 고른 비율은 낮았고(탐색 실행 6.7%, 실험 2 첫 회차 13~17%), 1·2단은 정규화 향상이 100% 였다. 교수님이 말씀하신 "규칙대로 결정해서 틀린다"보다는 "규칙이 좁아서 도움이 안 된다"는 모습이다.
2. **노트를 한 번 더 넓게 고쳐 쓰는 것만으로 3단이 조금 올랐다.** 반례가 있든 없든 비슷했다(+5.0 / +8.3%p, 구간이 0 에 닿음).
3. **제안자에게 문제를 보여주지 않는 것이 더 잘 옮겨 갔다.** 기출 점수는 같은데(98% 대 100%) 다른 측면은 76.7% 대 95% 였다. 지금 페이지 루프가 쓰는 "문제를 보지 않는 제안자" 규칙을 지지하는 방향이다.

## 7. 한계 (발표에 그대로)

- 9주차 한 주차, 단마다 18~20문항. 큰 차이만 구분된다. O 의 구간 반폭이 약 23%p 다.
- 구간은 문항 표본의 우연만 담는다. 같은 루프를 다시 돌릴 때의 차이는 담지 않는다(실험 1·2 의 기준선이 68.5% 와 70.4% 로 달랐다).
- 학습자는 LLM 이다. 사람 학생의 전이와 같다고 주장하지 않는다.
- 평가 문항도 LLM 이 출제했다(검증자와 강한 풀이자로 거름, 사람 전문가 검토 없음).
- 노트 항목에 "보기 번호·문항 번호 금지, 3문장 이하" 제약을 걸었고 이것은 `O_암기` 를 낮추는 쪽으로 작용한다.
- 3단은 기출 개념 15개 중 14개만 덮는다.

### 왜 한 주차뿐인가 (질문 대비)

표본을 늘리려고 10주차로 같은 실험을 반복하는 것을 검토했고, 접었다(2026-11-25).

- 10주차 공개 문제 은행을 새로 만들었다(`assets/data/quiz/week10-agent.json`, 43문항 중 자동 채점 30문항). 출제 → 검사 → 풀이 시험 → 검증 → 수정 1회를 거쳤다.
- 그런데 풀이자가 **자료 없이도 84.4%** 를 맞혔다(문항당 3회, 한 번이라도 틀린 문항은 6개). 10주차 주제(SINDy, 심볼릭 회귀 등)는 널리 알려진 내용이라 풀이자가 이미 알고 있다.
- 올라갈 여지가 15.6%p 뿐이면(9주차는 31.5%p) 향상도 오버피팅도 그보다 클 수 없고, 30문항의 구간 폭이 그와 비슷하다. 무엇이 나와도 판정할 수 없는 실험이라 돌리지 않았다.
- 교훈: 이 측정법은 **풀이자가 모르는 내용**이어야 작동한다. 주차를 늘리는 것보다 풀이자가 모르는 문항(강의 고유 사례, 구두 설명)을 늘리는 것이 먼저다.

## 8. 방법론에서 배운 것 (발표 소재)

- **사전 등록이 결론을 지켰다.** 보조 분석(정규화 향상)에서는 구간이 0 을 넘지만, 판정은 주 분석으로 하기로 미리 정했으므로 "확인 못 함"으로 보고했다.
- **동결 전 독립 검토가 치명적 버그를 잡았다.** 사용량 제한이나 빈 응답이 오답으로 채점돼 저장되는 문제였고, 탐색 실행에서 실제로 15회 일어났다. 확정 실행에서 일어났다면 오버피팅이 부풀려졌을 것이다.
- **탐색 실행과 확정 실행을 나눴다.** 프롬프트는 기출만으로 다듬고, 평가 문항은 동결 뒤에 처음 풀었다. 실험 2 의 탐색 실행에서 "고쳐 쓰기가 전부 버려져 처치가 작동하지 않는" 문제를 평가 문항을 보기 전에 찾았다.
- **코드가 약속을 강제한다.** 커밋되지 않은 변경이 있거나 문항 집합의 해시가 다르면 확정 실행이 시작되지 않고, 리포트가 이미 있으면 다시 돌릴 수 없다.

## 9. 슬라이드 구성 제안 (5장 안팎)

1. **피드백과 질문** — 교수님 피드백 두 가지 → "오버피팅을 전이로 쪼개고, 반례로 줄여 본다"
2. **왜 노트 설정인가** — 페이지 조건의 천장(95~100%) → 노트만 주는 설정(65~74%). 2절 표 + 4절 마지막 표
3. **전이 사다리와 사전 등록** — 3절 그림, 가설 H1~H3 한 줄씩
4. **결과** — 실험 1 그림(`final_ladder_exp1.png`)과 실험 2 표. "방향은 일관, 기준에는 미달, 반례는 구분 못 함"
5. **배운 것과 한계** — 6절 관찰 세 가지, 8절 방법론, 7절 한계

발표 대본에 넣을 한 문단:

> 교수님 피드백대로 오버피팅을 교육의 전이 관점에서 둘로 나누고, 메모리 규칙의 반례 문항으로 줄여 보려 했습니다. 기출 문제를 본 루프는 기출 점수를 30%p 올렸지만 같은 개념의 다른 측면에서는 8~10%p 밖에 오르지 않았습니다. 두 번 돌려 두 번 다 같은 방향이었지만, 미리 정해 둔 기준에는 근소하게 못 미쳤기 때문에 "확인했다"고 말씀드리지 않겠습니다. 반례 처치는 단순히 한 번 더 고쳐 쓰는 것과 구분되지 않았습니다. 다만 그 과정에서, 이 설정의 오버피팅이 "틀린 규칙을 따라서"가 아니라 "노트가 좁아서" 생긴다는 것을 보았습니다.
